## Affected Pages/Routes
- `/pricing` — new lineup (Free / Student $10 / Pro $50 / Ultra $100 / PAYG token packs). Card numbers must be generated from PRICE_TABLE, not hand-typed. Verify no plan shows a price the billing engine cannot charge.
- `/pricing#credits` — token pack purchase. New `tokens_*` slugs must be ONE-TIME (never schedule a renewal). Legacy `credits_*` slugs must still validate for in-flight checkouts.
- `/ws/[workspaceId]/os` — chat. A one-line turn and a deep tool-loop turn in the same thread must burn materially different token amounts.
- `/ws/[workspaceId]/os` Home widget — wallet KPI now renders integer tokens, not credits.
- `/ws/[workspaceId]/knowledge-base` — spend panel copy must no longer say "tokens" for LLM tokens (collides with the currency name).
- `/report/[id]` and `/ws/[workspaceId]/reports/[id]` — PR-2: the "2/2 Projects → Replace" gate must be gone; Create must succeed.
- Sidebar workspace switcher — PR-2: no "Upgrade for more" gate, and no orphaned "1/1 workspaces" readout.

## Key Interactions to Verify
- Student checkout → Clerk `paymentAttempt.updated` → 15,000 tokens granted → balance visible. THIS PATH HAS NEVER RUN IN PRODUCTION.
- Cancel a paid subscription → allowance clamps down (Pro→Free zeroes, Pro→Student clamps 75k→15k) → a ledger row explains the drop.
- Buy a token pack → +N purchasedUnits, no `amount_mismatch`, and no monthly re-charge scheduled.
- Send a cheap chat turn, then an expensive tool-loop turn → the second settles materially more; the unused reserve is refunded on the first.
- Exhaust the wallet → `out_of_credits` block, then top up → work resumes.
- PR-2: create more workspaces / reports / org members than the old caps allowed → blocked only by tokens, never by a count.
- PR-2: "Add to Project → Create New Project" with an existing project present → no Replace gate.

## Edge Cases
- Chat turn where the backend never reports tokens → 60-token floor, stamped as a fallback, NOT a full-reserve charge.
- Chat turn abandoned after reserve (stream dies, tab closed) → refunded by the 1h sweeper, user charged nothing.
- Chat turn costing more than the 400-token reserve → charged at the ceiling and stamped `clamped` (this is the signal the reserve is too low).
- Approval-resume and POST retry of the same turn → charged exactly once.
- Two tabs sending chat + generating an image against the same wallet → no overdraw (OCC).
- A KB ingest reserved before the tariff deploy and settled after → must not overcharge.
- Unknown / renamed Clerk plan slug → a `billing_events` row and a staff alert, never a silent no-op.
- Free-tier user at 15/15 daily chat turns → next turn is metered, not blocked.
- PR-2: fresh free user with a claimed workspace on the report route → must still land on "Continue with agent", NOT flip to "Create Project".
- PR-2: scripted mass workspace creation → stopped by the abuse rate limit, not by a plan cap.
- PR-2: 6th concurrent report → blocked by the concurrency guard with a distinct error code (not a `*_limit_reached` billing error).

## Critical Paths
1. Real prod checkout → grant → burn → visible balance. Until this is proven, PR-2 stays gated.
2. Chat metering correlated across all three evidence streams (browser balance ↔ Convex `usage_operations.settledUnits` ↔ LangSmith trace token counts). LangSmith is REQUIRED here.
3. Migrations on prod: `retirePlanSlugs` then `retariffPlanAllowances`, dry-run first, then a re-run proving idempotency (second run grants nothing).
4. The two live `agency` orgs (Basaev, Sacred Mandala) keep working after migrating to `ultra`, and their legacy credits survive as purchasedUnits.
